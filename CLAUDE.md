## Files
- `index.html`, `style.css`: UI. CSS has many later overrides; new rules are appended at the end.
- `data.js`: `categories` and `bhajans`: every song in permanent-number order (95 songs, numbers 1-98; the original 65 have ids 101-165, the community songs moved in on 2026-10-04 keep their `Date.now()` ids, `community`, `submittedAt` and contributor fields). Each song has `no`, `lyrics` (`full`/`partial`), `yt` (YouTube video id or ""), and `hindi`/`roman` as template literals. Generated by `C:\Nitesh\bhajan-youtube\build-data.mjs` (outside the repo); later edits by hand are fine. UTF-8 with Devanagari and emoji.
- `copyright.html`: copyright policy and contact email bhajanhits.contact@gmail.com (linked from the footer and the partial-lyrics note).
- `functions/api/report.js`: POST /api/report from the "⚑ Report" popup on song pages (song, reason, comment, optional email). Saved to KV key `reports` (newest 300 kept); the owner reads them in the Cloudflare dashboard. No email is sent (owner choice; email alerts could be added later with a sending service). Spam guards: hidden trap field, length limits, no links, one report a minute per browser.
- `app.js`: client logic (numbering, search, filters, favorites, reader with YouTube player and partial-lyrics note, home extras, submit dialog). Plain script, no modules; check with `node --check app.js`.
- `sw.js`: network-first cache `bbs-static-vNN`. Bump NN whenever a cached asset changes, AND update the matching `?v=NN` on `style.css`, `data.js` and `app.js` in index.html (the deploy fails if they differ). Reason: the bhajanhits.com zone serves JS/CSS with `max-age=14400` (4 h) while HTML is `max-age=0`; without the version query, phones paired new HTML with an old app.js and showed an empty list (2026-09-28).
- `functions/api/submit-bhajan.js`: POST /api/submit-bhajan (Gemini guardrail + formatting + lyrics rights, YouTube video search, then KV save).
- `functions/api/bhajans.js`: GET /api/bhajans (community songs from KV, `Cache-Control: public, max-age=30`). Skips numbers <= `MOVED_TO_DATA_JS` (98; those are in data.js) and sends only the opening lines of `partial` songs.

## Community submissions
1. Pasted text is pre-checked before any AI call: duplicate lyrics, links, emails, phone numbers.
2. Gemini (`gemini-3.8-flash`, fallback `gemini-3.5-flash`, busy responses retried) gets the rules as `systemInstruction`; the submission is fenced in `<submission>` tags as untrusted content. It also checks contributor name/city (shown publicly).
3. Server-side checks on the AI output: allowed deity/type lists, length caps, no links/emails/phones, Hindi must be Devanagari, Romanized must be Latin, name/city letters only. Gemini safety blocks become polite rejections.
4. Duplicate check: title slug, sound-alike title (`titleSound`), Hindi title, and character-trigram similarity of the opening lyrics (spelling variants folded: aa/a, ee/i, kh/k, chandrabindu...) against data.js and saved submissions. Thresholds 0.7 overall / 0.9 containment (min 40 trigrams). Calibrated 2026-10-04: distinct songs <= 0.66 (the two Hanuman aarti versions), all known re-submissions caught. data.js holds only 4 lines of partial songs, so short openings rely on the title checks. Side effect: a second genuine version of an existing song is rejected.
5. Saved to ONE KV key `submissions` (JSON array; one key because KV free tier limits list operations). Entry `id` = `Date.now()`, `community: true`, `submittedAt`, `lyrics` (`full` if Gemini says traditional, else `partial`; full text always kept in KV), `yt` (best embeddable video found with `YOUTUBE_API_KEY`, 100 of 10,000 free daily units per song; "" if none or no key), `contributorName/Location`, and permanent number `no`. Older entries may have `youtubeUrl`; it is no longer used.
6. Removing a bad entry: edit the `submissions` value in Cloudflare KV. Two submissions at the same instant can overwrite each other (acceptable at current traffic).
7. Gemini billing: paid Cloud Prepay, $5, auto-reload off (hard limit). When credit runs out, submissions fail with a friendly message; browsing is unaffected.
8. Live guardrail test (real Gemini, in-memory KV, saves nothing): `node C:\Nitesh\bhajan-guardrail-test\guardrail-live-test.mjs [case numbers]` (kept outside the repo). Re-run after changing the prompt or checks.

## Song numbers
- Owner decision: NO numbers on lists (home, Newly added, Aaj ka Bhajan). The list is A-Z with letter headings. A small "Song #N" shows only on the song page, and searching a number (24 or #24) still finds it, so a group leader can say "open 24".
- Numbers are permanent and stored as `no` in data.js (the original 65 kept their A-Z numbers 1-65). Community numbers are assigned by the server as the next free number (`LAST_BUILTIN_NUMBER = 98` in submit-bhajan.js; KV still holds 66-98 too). 67, 90 and 94 were duplicates, deleted on owner's request (2026-10-04): retired, never reuse. If a song is ever added to data.js by hand, give it an explicit `no:` above the current highest. Never renumber.

## Home page and navigation
- Compact by owner preference (no big hero). Header: brand, ♡ Favorites (count badge), 🕘 Recently viewed (both toggle their view), "+ Submit". There is no left menu any more.
- Below the search: type tabs Bhajan / Aarti / Chanting / Mantra / All with counts (default Bhajan; Chalisa and Sundarkand appear under All), deity quick-pick chips, compact "Aaj ka Bhajan" (changes daily) and "Newly added" strip, then the A-Z list with deity-coloured cards and a "New" badge for 30 days.
- Search, Favorites and Recent ignore the type tab (they look across all types). Recently Viewed is in time order without letter headings.
- "Chanting" = naam-jaap / dhun / kirtan where one or two lines of divine names repeat many times (e.g. "Hare Rama Hare Krishna", "Shri Krishna Govind Hare Murari"). Gemini is told this definition. No built-in song is labelled Chanting yet.
- Reader: songs with `yt` show a YouTube thumbnail; tapping loads YouTube's official player (youtube-nocookie) above the lyrics on phones and beside them (sticky) on wide screens. The player must stay visible (no audio-only tricks; YouTube terms). Partial songs show the opening lines plus a "View full lyrics (Google Images)" link.

## Lyrics copyright (owner decisions, 2026-10-04)
- Full lyrics only for traditional texts (classic aartis, stotras, saints' compositions) and folk / kirtan-mandali / languriya songs with no known writer. Songs tied to a film, a named modern lyricist or a label release are `partial`: first stanza, at most 4 lines (same rule in build-data.mjs, app.js `openingLines`, bhajans.js `excerpt`).
- Classification evidence: lyricist credits in YouTube video descriptions (`C:\Nitesh\bhajan-youtube\fetch-credits.mjs`), the owner's review page (`review.html` there), then owner approval. Credits are a guide, not proof.
- Full original texts are archived outside the repo in `C:\Nitesh\bhajan-backups\` (full-lyrics-2026-10-04.json, data-before-copyright-2026-10-04.js); the repo history still has them, so the repo should be private.

## Gotchas
- Git Bash: heredocs and `node -e` in this environment can drop backslashes; write files containing regexes with the editor tools, then verify. With `MSYS_NO_PATHCONV=1`, use `-o NUL` instead of `/dev/null` for curl.
- Line endings: index is LF, working copy CRLF (`core.autocrlf=true`); check `git diff -b` before assuming real changes.
- VS Code "content of the file is newer": the owner should Revert File, never Overwrite.
- Headless Chrome screenshots here have a 500px minimum layout width.
